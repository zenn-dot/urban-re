# URBAN RE:START — прототип с аккаунтами

Исходный прототип (одностраничный `index.html`: каталог, поиск и фильтры, карточка объекта, AI-архитектор (демо), форма размещения, тарифы) сохранён: его логика и дизайн не переписывались, изменения точечные. Добавлены регистрация, вход, профиль, избранные объекты и сохранённые демо-концепты.

## Запуск

Требуется **Node.js ≥ 22.13** (используется встроенный `node:sqlite`). Внешних npm-зависимостей нет.

```bash
npm start       # http://127.0.0.1:3000
npm test        # автотесты API (10 тестов, БД в памяти)
```

`npm install` не обязателен (зависимостей нет; `package-lock.json` приложен).

Открывать нужно **через сервер** (`http://127.0.0.1:3000`), а не двойным кликом по файлу: без сервера каталог откроется, но регистрация и вход покажут «Сервер недоступен».

## Как работает аутентификация

- Сервер `server/index.js` — Node `http` + SQLite (`data/urban.db`, создаётся автоматически). Он же отдаёт `public/index.html`.
- Пароли хранятся только как **scrypt-хэш с уникальной солью**; пароль не попадает ни в localStorage, ни в ответы API.
- После входа сервер выдаёт случайный токен сессии в cookie `urs_session` (**HttpOnly, SameSite=Lax**, плюс `Secure` при `COOKIE_SECURE=true`). В БД хранится только SHA-256 токена. Сессия живёт 7 дней, переживает обновление страницы и удаляется при выходе. Смена пароля завершает остальные сессии.
- Валидация и в браузере, и на сервере: имя, формат email, пароль не короче 8 символов с буквами и цифрами, совпадение паролей, запрет дублей email (без учёта регистра).
- Защита: ограничение частоты попыток входа/регистрации, проверка `Origin` и `Content-Type: application/json` для изменяющих запросов (CSRF), одинаковое сообщение при неверном email или пароле, базовые security-заголовки.
- Профиль доступен только после входа: клиент перенаправляет на страницу входа, а все данные аккаунта в `/api/*` проверяются сервером.

## Ограничения

- Это **локальная демо-версия, а не продакшен**: нет подтверждения email, восстановления пароля, смены email, 2FA и удаления аккаунта; ограничитель частоты хранится в памяти процесса; SQLite-файл рассчитан на один сервер.
- Для публикации в интернете нужны HTTPS (`COOKIE_SECURE=true`) и резервное копирование папки `data/`.
- Избранное работает для 3 встроенных объектов каталога (id 1–3). Объекты, добавленные формой «Продать объект», живут только в памяти страницы (как и раньше) и кнопки ♡ не имеют.
- Регистрация сообщает, что email уже занят (компромисс в пользу удобства; это позволяет проверять наличие адреса).
- Платежи, реальные объявления и AI-генерация остаются неготовыми, как и в исходном прототипе.

## Переменные окружения (все необязательны)

См. `.env.example`. Сервер читает `process.env` напрямую и `.env`-файлы сам не загружает: `PORT`, `HOST`, `DATABASE_PATH`, `COOKIE_SECURE`, `ALLOWED_ORIGINS`. Внешние сервисы и ключи не нужны.
